How this maps to a real build: this Spring Boot app already has the split described in the brief, just running as one deployable. DoctorService (see DoctorController) owns doctor profiles and slot availability behind GET /api/doctors and GET /api/doctors/{id}/slots; AppointmentService (see AppointmentController) owns bookings and status behind POST /api/appointments and DELETE /api/appointments/{id}. Booking a slot calls DoctorService.checkAvailability() before AppointmentService.create(), the same handshake as the original demo. To go fully micro, move DoctorService/DoctorController into their own Spring Boot app on port 8081, keep AppointmentService/AppointmentController on 8082, and swap the direct method call for a RestClient/WebClient HTTP call.
