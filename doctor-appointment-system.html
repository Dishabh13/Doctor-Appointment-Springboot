How this maps to a real build: everything here runs in one page for the demo, but the logic is split exactly like the two services in the brief. The DoctorService object owns doctor profiles and slot availability (GET /doctors, GET /doctors/{id}/slots); the AppointmentService object owns bookings and status (POST /appointments, DELETE /appointments/{id}). Booking a slot calls DoctorService.checkAvailability() before AppointmentService.create() — the same handshake shown in the sequence diagram. Lift each object into its own Spring Boot app on ports 8081/8082 and swap the direct call for a RestClient/WebClient HTTP call, and you have the microservices version.
